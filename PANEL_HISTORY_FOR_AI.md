# Alice Light Web Panel Remote — контекст для другого ИИ

## Цель пользователя

Панель управления Яндекс Станцией Лайт **первого поколения** с прошивкой HackAlice. Веб-сайт, backend, настройки, авторизация и мониторинг должны работать на отдельном ПК или Ubuntu Server. Колонка должна остаться максимально нетронутой: предпочтительно ноль дополнительных файлов и отсутствие постоянного агента. Предпочтительны подтверждённые штатные интерфейсы; нельзя выдумывать команды. При отсутствии проверки показывать функцию как неподдерживаемую.

Требовались обзор состояния, плеер, RGB, настройки, API, адаптеры Quasar/Glagol/SSH/ADB, установка на Linux/Ubuntu, systemd, mock-режим и мобильный интерфейс. Позже пользователь попросил запуск в локальной сети на Windows через Node.js.

## Дизайн

Пользователь приложил скриншот светлой панели Станции Лайт 2 с оранжевыми акцентами, левым меню, карточками температуры/RAM/Wi-Fi/аптайма, крупным изображением устройства, громкостью и плеером. Для первой Лайт блок дисплея часов должен отсутствовать. Текущий UI находится в `web/index.html`; изображение устройства выполнено CSS-иллюстрацией, а не реальной фотографией.

## Что реализовано

- Python/FastAPI backend: `backend/app.py`, `requirements.txt`, `install.sh`, `start.sh`, `stop.sh`, `update.sh`, `uninstall.sh`, шаблон `systemd/alice-light-panel.service`.
- Node.js backend без npm-зависимостей: `node/server.js`, `package.json`, `start-windows.ps1`.
- API: `/api/status`, `/api/system`, `/api/player`, `/api/player/control`, `/api/lighting`, `/api/settings`; в Node также `/api/health`.
- Авторизация через `ALICE_PANEL_TOKEN` в заголовке `X-Panel-Token`. Секреты и настройки хранятся на ПК; `data/`, `.env`, `.venv/` исключены через `.gitignore`.
- Режим mock. SSH-режим выполняет фиксированные read-only команды для `/proc/uptime`, `/proc/meminfo`, температуры и свободного места. SSH настроен на строгую проверку host key. IP настроек ограничен частными адресами.
- Адаптеры Quasar, Glagol, ADB и Lighting присутствуют как заглушки доступности. Непроверенные команды плеера/RGB/перезапуска возвращают 501 или отключены в UI.
- Мобильная верстка и форма настроек.

## Проверки и ограничения

- Синтаксис Python проверен `compileall`; Node проверен `node --check`.
- Тесты разбора данных Node проходили. HTTP integration test не смог открыть локальный порт в облачном окружении (`EPERM`), поэтому запуск на Windows фактически не проверен.
- Запрошенные сайты HackAlice и исходный репозиторий `dimap/yandex-station-web` не удалось изучить в начальном окружении из-за отказа сетевого прокси. Следовательно, совместимость Quasar/Glagol/RGB sysfs и команд управления с первой Лайт не подтверждена.
- Проект является работающей основой, **не завершённой аппаратно проверенной панелью**. Не утверждать, что плеер, подсветка и перезагрузка реализованы.
- Веб-мастер первоначальной настройки пока упрощён. Требования безопасности для публикации в интернет не завершены; запускать только в доверенной локальной сети, желательно за HTTPS-прокси.

## Запуск

Ubuntu: `./install.sh`, задать `ALICE_PANEL_TOKEN`, затем `./start.sh`. По умолчанию backend слушает `127.0.0.1:8765`; для LAN задать `ALICE_BIND` адресом ПК и ограничить порт firewall.

Windows: Node.js 20+, Git; клонировать репозиторий, задать `ALICE_PANEL_TOKEN`, `ALICE_BIND=0.0.0.0`, выполнить `start-windows.ps1`. Подробности в `README.md`. Токен вводится в браузере; хранится в sessionStorage.

## Важные следующие шаги

1. Изучить подтверждённые интерфейсы именно первой Станции Лайт и HackAlice.
2. Подключить только проверенные команды Quasar/Glagol; расширять capability detection.
3. Проверить SSH-мониторинг и API на реальном устройстве, затем привести Linux и Node реализации к одинаковому поведению.
4. Исправить ограничения безопасности и удобства установки по результатам тестов.
5. Сверить UI со скриншотом и заменить CSS-иллюстрацию корректным изображением первой Лайт при наличии лицензированного ассета.
